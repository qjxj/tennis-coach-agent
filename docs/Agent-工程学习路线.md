# Agent 工程学习路线（单一主线版）

> 原则：**一条主线、一个仓库、七个阶段、每阶段一个可验收产出。**
> 不再换项目，不再被环境问题带偏。

---

## 0. 先建立心智模型

**Agent ≠ LLM。**

```
Agent = LLM（决策）
      + Tools（能力）
      + Loop（循环直到完成）
      + State（跨轮记忆）
      + Eval（证明它变好了）
```

缺任何一项，它都只是"会聊天的程序"。

**判断标准**：给一个没见过你代码的人讲，他能不能立刻说出这五样分别在哪。

---

## 主线仓库

统一用 `tennis_coach/`，所有阶段都往这里加东西，不另起项目。

```
tennis_coach/
├── core/          # ToolResult、上下文裁剪、trace
├── tools/         # 每个工具一个文件
├── agent/         # 编排、Prompt、状态
├── api/           # FastAPI + WebSocket
├── evals/         # 用例、基线、报告
└── pose/          # 已完成：姿态 → 指标
```

---

## 阶段 1：Tool Calling 基本功

| 项 | 内容 |
|---|---|
| 学什么 | JSON Schema、`Annotated`、枚举约束、工具描述写"不适用场景"、失败返回 vs 抛异常 |
| 练什么 | 把已有姿态管线包成 `@tool analyze_stroke` |
| 产出 | `tools/analyze_stroke.py` + `core/schema.py`（`ToolResult`） |
| 验收 | 打印 `convert_to_openai_tool(...)`，每个参数都有 description |
| 已有资产 | `pose/` 全套（视频→指标→可视化） |
| 缺口 | 没有 `@tool`、没有统一返回结构 |

**核心认知**：模型看不到你的 Python，只看到 schema。工具写不好，Agent 必然乱调。

---

## 阶段 2：单 Agent 循环

| 项 | 内容 |
|---|---|
| 学什么 | ReAct 循环、`bind_tools`、`tool_calls` 解析、终止条件、最大步数 |
| 练什么 | 手写 100 行 LangGraph：model → tools → model |
| 产出 | `agent/mini_loop.py`（不依赖 deepagents） |
| 验收 | 问"分析这个视频"，模型自己决定调 `analyze_stroke`，拿到结果再回答 |
| 已有资产 | 原项目的 `examples/mini_agent.py` 可以照搬结构 |
| 缺口 | 网球项目里还没有 |

**核心认知**：循环的终止不是"模型说完了"，而是"没有 tool_calls 且产生最终答案"。

---

## 阶段 3：上下文工程

| 项 | 内容 |
|---|---|
| 学什么 | token 预算、工具结果裁剪、摘要、分层注入、证据引用 |
| 练什么 | 把 9000 个关键点数字压成"摘要 + 异常标记 + 文件引用" |
| 产出 | `core/context.py`（裁剪策略）+ 对比实验：不裁剪 vs 裁剪 |
| 验收 | 同一任务，token 消耗下降 ≥ 80%，结论质量不降 |
| 已有资产 | 原项目的"首轮注入"、"只搬运不压缩"思路 |
| 缺口 | 网球项目的数据量更大，问题更真实 |

**核心认知**：上下文不是越多越好。**给模型"异常"比给"原始数据"更有用。**

---

## 阶段 4：多智能体编排

| 项 | 内容 |
|---|---|
| 学什么 | 路由（description 决定调用）、子智能体隔离、星型拓扑、信息折损 |
| 练什么 | 拆出「质检助手」+「动作分析助手」+「诊断助手」 |
| 产出 | `agent/orchestrator.py` + `agent/subagents/*` |
| 验收 | 脏视频先被质检拦住，不会进入分析流程 |
| 已有资产 | 原项目完整实现过（搜索/DB/RAG 三专家） |
| 缺口 | 网球项目里要重新拆，但方法论可复用 |

**核心认知**：主智能体不干活，只做决策与汇总；子智能体只干一件事。

---

## 阶段 5：可靠性

| 项 | 内容 |
|---|---|
| 学什么 | 超时、重试分类、降级、拒答、路径沙箱、幂等 |
| 练什么 | 异常指标（如 `backswing_height=3.07`）触发"拒答 + 建议重拍" |
| 产出 | `core/rules.py` + `core/verify.py` |
| 验收 | 故意给烂视频，系统拒绝给建议并说明原因，而不是硬编 |
| 已有资产 | 原项目的路径沙箱、错误码、`retry` |
| 缺口 | 网球场景的"质量门禁"要自己定义 |

**核心认知**：**会拒答的 Agent 才可信。** 判定规则进代码，不进 Prompt。

---

## 阶段 6：评测与可观测（最容易被跳过，也最值钱）

| 项 | 内容 |
|---|---|
| 学什么 | 断言过程而非文本、基线对比、trace、LLM-as-judge 的偏差 |
| 练什么 | 15 条用例 + 2 条基线（LLM 直接看视频 / 固定流水线） |
| 产出 | `evals/run_eval.py` + `evals/cases.jsonl` + 一份报告 |
| 验收 | 能回答"你的系统比直接问大模型好在哪"，且给得出数字 |
| 已有资产 | 原项目 `evals/` 可复用 80% |
| 缺口 | 网球项目还没有 |

**核心认知**：没有评测，所有"优化"都是玄学。

---

## 阶段 7：产品化

| 项 | 内容 |
|---|---|
| 学什么 | WebSocket 进度推送、异步任务、成本统计、并发限制 |
| 练什么 | 上传视频 → 实时进度 → 报告页 |
| 产出 | `api/server.py` + 前端页 |
| 验收 | 5 分钟视频能边处理边推进度，前端不卡 |
| 已有资产 | 原项目 FastAPI + WS + ContextVar 全套 |
| 缺口 | 网球项目的长任务进度更明显 |

---

## 一页纸总览

| 阶段 | 产出 | 门槛 |
|---|---|---|
| 1 Tool | `@tool` + `ToolResult` | schema 有 description |
| 2 Loop | `mini_loop.py` | 模型自主调工具 |
| 3 Context | `core/context.py` | token 降 80% |
| 4 Multi-Agent | `orchestrator.py` | 脏数据被拦住 |
| 5 可靠 | 拒答 + 规则引擎 | 烂视频敢拒 |
| 6 评测 | 15 用例 + 2 基线 | 讲得出数字 |
| 7 产品 | WS 进度 + 报告页 | 能演示 |

---

## 每阶段的固定动作

1. **先写验收标准，再写代码**
2. **每阶段结束跑一次评测**（哪怕只有 5 条）
3. **留一行决策记录**：为什么这么选
4. **不换项目**：所有产出落在 `tennis_coach/`

## 三个反面教材（前面踩过的）

| 反面 | 后果 |
|---|---|
| 一上来跑模型、调环境 | 花时间在"耗材"上，Agent 层一片空白 |
| 选题反复换（论文→工业→网球） | 每个方向都浅 |
| 没有验收标准就写代码 | 写完不知道算不算完成 |
